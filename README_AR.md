# عيسى ستور — نسخة مستقلة قابلة للنشر

هذا مشروع Next.js + Supabase كبداية تشغيلية فعلية، وليس صفحة صورة ثابتة. يحتوي على متجر عربي RTL، كتالوج من قاعدة البيانات، تصنيفات، سلة، تسجيل طلبات، تحويل الطلب إلى واتساب، وتسجيل دخول لوحة الإدارة وإدارة المنتجات والتصنيفات والطلبات.

## قبل التشغيل

- تحتاج حساب استضافة (مثل Vercel) وحساب Supabase لقاعدة البيانات والمصادقة.
- الدومين الخاص عادةً يحتاج شراءً منفصلًا. لا يمكنني إنشاء الحسابات أو ربط الدومين نيابة عنك دون تسجيل الدخول والتفويض منك.
- المشروع لا يسترجع منتجات Whacka؛ المنتجات ستُدخل من لوحة الإدارة كما اخترت.
- هذه النسخة لا تتضمن بعد بوابة دفع إلكتروني أو حساب تكلفة شحن تلقائي أو رفع ملفات العملاء. الدفع الظاهر هو اختيار طريقة فقط؛ لا تُدخل بيانات بطاقة في هذا الموقع.
- اختبر طلبًا تجريبيًا قبل استقبال عملاء حقيقيين.

## 1) إنشاء قاعدة البيانات

1. أنشئ مشروعًا جديدًا في Supabase.
2. افتح SQL Editor وشغّل محتوى `supabase/schema.sql`.
3. من Authentication > Users أنشئ حساب المالك بالبريد وكلمة مرور قوية.
4. انسخ UUID لحساب المالك، ثم نفّذ في SQL Editor (استبدل UUID):
   ```sql
   insert into public.profiles(id, full_name, role)
   values ('UUID-حساب-المالك','مالك عيسى ستور','owner')
   on conflict (id) do update set role='owner';
   ```
5. من Project Settings انسخ Project URL و anon/public key. لا تضع Service Role Key في أي متغير يبدأ بـ `NEXT_PUBLIC_`.

## 2) تشغيل محلي

```bash
npm install
cp .env.example .env.local
# املأ NEXT_PUBLIC_SUPABASE_URL و NEXT_PUBLIC_SUPABASE_ANON_KEY
npm run dev
```
افتح `http://localhost:3000`. لوحة الإدارة: `/admin/login`.

رقم واتساب الافتراضي الموجود في `.env.example` هو `201001046629` (رقم مصر بصيغة دولية دون +). عدّله إذا رغبت.

## 3) النشر والدومين

1. ارفع مجلد المشروع إلى مستودع GitHub خاص بك.
2. استورد المستودع إلى Vercel.
3. أضف متغيرات البيئة من `.env.example` في إعدادات Vercel.
4. انشر المشروع، واختبر الصفحة والطلب ولوحة الإدارة.
5. اشترِ الدومين الذي تختاره، ثم أضفه في إعدادات Vercel واضبط DNS حسب التعليمات التي تظهر لك.
6. أضف الدومين في إعدادات Authentication > URL Configuration داخل Supabase.

## الأمان والحدود الحالية

- لا تشارك كلمة مرور المالك أو Service Role Key.
- سياسات RLS تمنع العملاء من قراءة الطلبات أو إدارة المنتجات.
- إنشاء الطلب عام حتى يستطيع العملاء الشراء دون حساب، كما أن الطلبات لا تظهر إلا للموظفين المصرح لهم.
- قبل التوسع: أضف تحققًا خادميًا للأسعار والمخزون، وحدودًا لمعدل إنشاء الطلبات، ورفع صور عبر Supabase Storage بسياسات وصول، وإدارة كاملة لحسابات الموظفين والشحن ووسائل الدفع، ورسائل إشعار موثوقة. لا تعتبر هذه النسخة جاهزة لمعالجة بطاقات الدفع أو بيانات حساسة دون مراجعة أمنية.

## هيكل المشروع

- `app/store.tsx`: واجهة المتجر والسلة وإرسال الطلبات.
- `app/admin/`: تسجيل الدخول ولوحة الإدارة.
- `lib/supabase/client.ts`: اتصال Supabase.
- `supabase/schema.sql`: الجداول وسياسات الوصول.
